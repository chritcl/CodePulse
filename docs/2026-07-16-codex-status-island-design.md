# Codex 实时状态灵动岛设计

状态：MVP 实施边界

目标平台：Windows

首版兼容：Windows 原生 Codex CLI、Codex App 原生 PowerShell 模式

## 0. MVP 边界

本功能的目标是让用户在 CodePulse 灵动岛中看到正在运行的 Codex 任务状态，而不是建立一套通用的 Hook 配置管理或文件事务框架。

- CodePulse 只管理用户层 %USERPROFILE%\.codex 中带有 CodePulse 标记的一条 Hook 配置。
- 首版支持现有的 hooks.json 或 config.toml 表示；无法明确判断该修改哪一个文件、配置无法解析、或 Hooks 被外部策略管理时，停止写入并给出人工处理提示。
- CodePulse 不扫描仓库级配置、插件 Hook、企业托管配置或用户磁盘上的全部仓库。
- Hook 事件只在 CodePulse 运行期间接收；不补偿历史事件，不保存完整命令、提示词、工具输入输出或项目文件内容。
- 配置写入采用预览、备份、临时文件校验和原子替换。预览后发现文件已变化时直接停止并要求重新预览。
- 首版不实现跨进程事务日记、崩溃后的自动恢复、文件句柄租约、文件 ID 比对、强制覆盖、复杂冲突状态机或全配置层语义去重。

后续只有在真实使用中证明这些能力必要时，才以独立需求重新评估。

## 1. 产品目标

用户能在紧凑岛、汇总列表和任务详情中看到：

- 当前最重要的 Codex 任务；
- 正在分析、读取、修改、运行命令、运行测试、等待授权、完成或失败的状态；
- 脱敏后的任务与操作摘要；
- CLI 或 App 来源；
- 是否已经安装 Hook、是否等待 Codex 信任、以及是否需要修复。

CodePulse 不控制 Codex，不替用户批准授权，不打开或定位 Codex 会话，也不替用户启用 Codex 的全局 Hooks 开关。

## 2. 产品形态

### 2.1 紧凑态

紧凑岛显示最高优先级的任务状态。例如：

    等待授权    CodePulse
    运行测试    3 个任务执行中
    执行失败    cargo test

等待授权首次出现时为强打断；最终失败首次出现时为强打断；完成和中断为软打断；普通运行不打断用户当前主岛。

### 2.2 汇总列表

展开后按最近活动时间显示活动会话。每个 sessionId 只保留一张卡片；新一轮任务更新同一张卡片，不建立历史列表。

### 2.3 任务详情

详情只显示项目名、脱敏任务摘要、当前阶段、脱敏操作摘要、来源与最近活动时间。首版不提供打开 Codex、继续任务、终止任务或授权按钮。

## 3. 可见状态

| 状态             | 说明                           | 灵动岛优先级 |
| ---------------- | ------------------------------ | ------------ |
| analyzing        | 正在分析任务                   | 普通         |
| reading          | 正在读取项目                   | 普通         |
| editing          | 正在修改代码                   | 普通         |
| running_command  | 正在运行命令                   | 普通         |
| running_tests    | 正在运行测试                   | 普通         |
| waiting_approval | 等待用户在 Codex 中授权        | 强打断       |
| completed        | 当前轮次完成，短暂保留         | 软打断       |
| failed           | 当前轮次最终失败，等待手动清除 | 强打断       |
| interrupted      | 长时间无活动或停止事件后的中断 | 软打断       |

中间工具失败不立即代表任务失败。只有 Stop 或明确结束事件给出失败结果时，任务才进入 failed。

## 4. 数据与隐私边界

Bridge 只发送状态展示所需的最小字段：

- 随机 eventId；
- sessionId、可选 turnId；
- 来源、项目显示名；
- 事件类型和阶段；
- 已截断且脱敏的任务摘要、操作摘要或错误摘要；
- 发生时间。

下列内容不得离开 Bridge stdin，也不得写入日志、状态快照或 Vue 状态：

- 完整提示词、完整命令和完整工具输入输出；
- 文件正文、代码片段、密钥、令牌和 Cookie；
- transcript 路径；
- 原始工作目录。

Bridge 与 Rust 接收端都要执行长度限制和脱敏。日志只记录错误码、来源和计数等非敏感元数据。

## 5. 最小架构

    Codex Hook
      -> codepulse-codex-bridge.exe
      -> 仅回环的本地 HTTP 接收器
      -> 单线程聚合器
      -> Rust 权威快照与 Tauri 事件
      -> Vue 灵动岛与设置页

Bridge 是一次性、静默退出的进程：读取一份 Hook 输入，生成最小事件，投递失败时返回成功退出码，不影响 Codex 自身工作流。

本地 HTTP 服务只监听 127.0.0.1，使用运行时随机令牌认证，限制请求体大小和队列长度。服务停止后不再接受事件。

聚合器在内存中维护会话卡片与最新快照。它只做 eventId 的有界传输重复过滤；不同配置层产生的独立事件不在首版尝试猜测性合并。运行时重启时取消旧接收器并清空快照，旧任务的晚到事件直接忽略。

## 6. Rust 与 Vue 的边界

Rust 负责：

- Bridge 协议、输入解析、脱敏和事件接收；
- 会话状态、优先级、超时、完成保留和失败判定；
- 最新快照、运行时启停、安装检查与配置写入；
- 向两个窗口广播状态变化。

Vue 负责：

- 紧凑态、列表、详情、清除失败任务和设置页；
- 消费 Rust 快照，不重新判断失败、超时或优先级；
- 在组件卸载时释放监听器和定时器。

新增 Codex 状态应放在独立的 codex 模块、composable 和展示组件中。IslandView.vue 只做现有多岛编排，不新增业务状态机。

## 7. Hook 安装、修复与卸载

### 7.1 检查与预览

设置页先调用只读检查，返回以下事实：

- 用户层配置目录是否存在；
- 可用的配置表示；
- Hooks 是否由 Codex 启用；
- CodePulse 标记是否存在、重复、损坏或指向旧 Bridge；
- 当前 Bridge 是否可运行。

安装、修复、卸载都先生成文字预览。用户确认前不写文件。

### 7.2 安全写入

确认安装或修复后的顺序如下：

1. 再次读取目标配置并比较预览时的摘要；发生变化则停止；
2. 将随应用发布的 Bridge 写入固定应用数据路径并做最小可运行检查；
3. 完整解析配置，在内存中只新增或修复 CodePulse 标记；
4. 为原配置创建时间戳备份；
5. 写入同目录临时文件，重新解析验证；
6. 原子替换正式配置；
7. 启动本地服务并执行一次本地自检；
8. 等待第一条真实 Hook 事件后才显示正常运行。

如果 Bridge 写入失败，不修改 Hook 配置。如果配置原子替换失败，保留原配置并报告失败。自检失败不回滚已成功写入的配置，而是显示需要修复，避免覆盖用户随后可能做出的修改。

### 7.3 卸载

卸载同样先重新检查和预览，然后：

1. 完整解析配置，只移除带 CodePulse 标记的条目；
2. 备份、写临时文件、重新解析并原子替换；
3. 停止接收器并清空内存快照；
4. 尝试删除不再被配置引用的 Bridge。

Bridge 删除失败只显示待清理提示，不回滚已正确完成的配置卸载。不得用旧备份覆盖用户的完整当前配置。

## 8. 设置页

新增 Codex 状态集成分组，包含：

    全局 Hooks：已启用 / 需在 Codex 中手动启用 / 由组织管理
    CodePulse Hook：未安装 / 已安装 / 等待信任 / 需要修复
    监听状态：未运行 / 等待事件 / 正常运行 / 服务异常
    最近事件与来源
    检测环境、预览安装或修复、预览卸载
    Codex 空闲时常驻、显示脱敏命令摘要

前两项显示来自 Rust 检查。后两个开关是普通显示偏好，不得启停接收器或修改 Codex 全局设置。

## 9. 异常处理

| 情况               | 行为                             |
| ------------------ | -------------------------------- |
| 配置无法解析       | 不写入，显示人工处理提示         |
| 预览后配置变化     | 停止操作，要求重新预览           |
| Hooks 未启用       | 显示官方启用提示，不代替用户修改 |
| 固定端口已占用     | 使用随机回环端口                 |
| 认证失败或请求非法 | 拒绝请求，不创建任务             |
| 队列已满           | 返回失败，Bridge 不重试          |
| Bridge 缺失或过旧  | 显示需要修复                     |
| 用户已有其他 Hook  | 完整保留                         |

## 10. 首版不做

- WSL、Linux 或跨环境 Hook 支持；
- 云端任务、编辑器扩展和历史事件补偿；
- 打开、定位、暂停、终止或继续 Codex 会话；
- 完整审计日志、完整工具调用展示和任务历史；
- 扫描全部配置层并自动去重；
- 跨进程文件事务、自动崩溃恢复和强制冲突处理。

## 11. 验收标准

完成时应满足：

1. 真实 Codex CLI 和 Codex App 都能产生至少一条状态事件；
2. UI 能正确显示运行、等待授权、完成与最终失败；
3. 用户已有非 CodePulse Hook 在安装、修复和卸载后保持不变；
4. 无效配置、配置变化和写入失败均不会覆盖用户文件；
5. 关闭 CodePulse 后不再显示旧任务，重新启动不补偿历史事件；
6. Bridge 与接收端均不记录敏感正文；
7. 前端测试、Rust 测试、类型检查和构建通过。
