# 阶段一：Bridge 与本地 HTTP 接收器

## 目标

建立一条可在测试环境独立验证的事件通道：Codex Hook 输入经过一次性 Bridge 清洗后，发送给 CodePulse 的本地回环 HTTP 接收器。

本阶段不写入真实 Codex 配置、不接入 Vue、不实现任务聚合逻辑。

## 新增边界

- Bridge 只处理一份 stdin 输入，成功或失败都静默退出；
- 服务只监听 127.0.0.1；
- 请求使用本次启动生成的随机令牌；
- 请求体、字段长度与队列均有上限；
- 接收器只验证并转交事件，不保存历史，不判断任务状态；
- 不实现跨进程服务恢复、多个 Runtime 所有权竞争或多层配置扫描。

## 建议文件

- src-tauri/src/codex/protocol.rs：事件 DTO、字段校验与脱敏工具；
- src-tauri/src/codex/bridge.rs：stdin 解析和 HTTP 投递；
- src-tauri/src/codex/server.rs：回环服务、令牌校验和有界发送端；
- src-tauri/src/codex/runtime_discovery.rs：当前端口与令牌的最小发现文件；
- src-tauri/src/bin/codepulse-codex-bridge.rs：Bridge 二进制入口；
- src-tauri/src/codex/mod.rs：模块导出；
- src-tauri/Cargo.toml：Bridge 二进制和必要依赖；

如当前项目的模块组织有更合适的既有位置，沿用既有位置，但不要创建通用插件框架或第二个 Cargo workspace。

## 任务 1：定义最小协议

定义版本号、来源、事件类型、阶段和 CodexBridgeEvent。事件只携带状态展示所需字段，所有文本在 Bridge 与服务端都重新截断和脱敏。

测试至少覆盖：

- 合法最小事件；
- 版本错误、缺少 sessionId、超长文本和控制字符；
- 敏感字段不进入公开事件；
- 序列化字段采用稳定命名。

## 任务 2：实现一次性 Bridge

Bridge 从 stdin 读取 Hook 输入，尽可能识别来源、项目显示名和事件类型。无法解析的输入直接成功退出；不得向 stdout 写日志或错误信息。

Bridge 读取运行时发现文件取得回环地址与令牌。发现文件不存在、服务不可达、请求超时或返回拒绝时均直接退出，不重试。

测试至少覆盖空输入、非法 JSON、合法输入、脱敏、发现文件缺失和 HTTP 失败。

## 任务 3：实现最小发现文件

CodePulse 启动接收器后，向应用数据目录写入包含端口、令牌、进程 ID 与创建时间的发现文件。写入使用临时文件后原子替换。

发现文件只用于让 Bridge 找到当前服务；旧文件或服务已停止时，Bridge 投递失败即可。首版不需要复杂的旧所有者清理和自动恢复。

测试启动服务后可读取发现文件，并验证停止服务后旧发现文件不会造成服务端错误。

## 任务 4：实现回环接收器

接收器应：

1. 只绑定回环地址；
2. 限制请求体大小；
3. 校验协议和令牌；
4. 将合法事件送入有界 channel；
5. 在 channel 已满时返回明确失败；
6. 在停止后拒绝新请求。

测试直接构造 HTTP 请求，覆盖错误令牌、超长请求、非法协议、合法入队、队列满和停止后的请求。

## 阶段完成门槛

- Bridge 在没有服务时不影响调用方；
- 合法测试事件能够从 HTTP 接收器进入 channel；
- 非法或未认证事件不进入 channel；
- Cargo 测试通过；
- 不修改真实用户配置，也不修改前端页面。
