# Codex 实时状态灵动岛 MVP 路线图

## 目标

在不控制 Codex、不保存用户项目内容、不破坏现有用户 Hook 的前提下，为 Windows 原生 Codex CLI 与 Codex App 显示实时任务状态。

本路线图优先交付可用链路。每一阶段都应能独立验证，不为尚未出现的并发、崩溃恢复或扩展场景建立通用框架。

## MVP 范围

- 一次性 Bridge 将 Hook 输入转成最小事件；
- 本地回环 HTTP 接收器和内存聚合器；
- Rust 状态快照与 Vue 灵动岛展示；
- 用户层 CodePulse Hook 的检查、预览、安装、修复和卸载；
- JSON 或 TOML 的完整解析、备份、临时文件校验和原子替换；
- CLI 与 App 的真实人工验收。

## 不在本次范围

- 多配置层扫描和跨层语义去重；
- 跨进程事务日记、自动崩溃恢复、文件句柄锁定和强制冲突恢复；
- 历史事件、完整审计、云端任务、编辑器扩展和 WSL；
- 控制、打开或定位 Codex 会话。

## 交付顺序

    阶段一：Bridge 与本地接收器
      -> 能用测试请求看到安全事件
    阶段二：内存聚合器与 Tauri 状态
      -> 能得到可订阅的最新任务快照
    阶段三：Agent 灵动岛 UI
      -> 能在 Widget 中展示真实或模拟快照
    阶段四：Hook 配置与设置页
      -> 用户能安全安装、修复和卸载

阶段四依赖前三阶段；前三阶段不依赖写入真实用户配置。开发和测试阶段使用临时目录和测试请求，真实配置只在最后验收时由用户明确确认。

## 最小数据流

    Hook stdin
      -> Bridge 清洗与截断
      -> 127.0.0.1 HTTP POST
      -> 协议和令牌校验
      -> 有界内存队列
      -> 聚合器更新快照
      -> Tauri 事件
      -> Vue Store 与岛组件

Bridge 只负责读取、清洗和投递。HTTP 层只负责回环、认证、大小限制和入队。聚合器拥有会话状态和 eventId 去重缓存。Vue 不复制业务判断。

## 必要接口

事件最少包含版本、eventId、sessionId、可选 turnId、来源、项目显示名、事件类型、阶段、脱敏摘要和发生时间。

公开快照最少包含 revision、生成时间、任务列表、代表任务、是否等待授权和当前监听状态。revision 只需在当前 CodePulse 进程内单调递增，用来让两个窗口丢弃较旧事件；不需要跨进程持久化。

设置页需要四个只读或操作接口：

- 检查当前集成状态；
- 生成安装或修复预览；
- 生成卸载预览；
- 确认执行已预览的动作。

预览结果只在当前应用进程中短期有效。确认前重新读取目标文件；摘要不一致时拒绝执行并要求再次预览。

## 配置写入规则

安装或修复：

1. 检查用户层配置与 CodePulse 标记；
2. 向用户展示将写入的文件、将新增或修复的条目和 Bridge 路径；
3. 确认后再次检查文件摘要；
4. 写入并验证 Bridge；
5. 在内存中修改解析后的配置；
6. 备份原文件，写入临时文件并重新解析；
7. 原子替换配置；
8. 启动服务并等待真实事件。

卸载：

1. 预览只会移除的 CodePulse 标记；
2. 确认后再次检查文件摘要；
3. 备份、临时写入、重新解析和原子替换配置；
4. 停止服务；
5. 尽力删除不再引用的 Bridge。

任何解析、检查、Bridge 写入或原子替换错误都应停止当前动作。不得尝试自动合并外部改动，也不得覆盖用户完整配置。

## 最小测试矩阵

| 类别     | 必测场景                                                       |
| -------- | -------------------------------------------------------------- |
| Bridge   | 空输入、非法输入、敏感字段移除、投递失败静默退出               |
| HTTP     | 非回环拒绝、错误令牌、超长请求、合法事件入队                   |
| 聚合器   | 新会话、阶段变化、eventId 重复、等待授权、完成、最终失败、超时 |
| UI       | 紧凑态、列表、详情、强弱打断、失败清除、监听器清理             |
| 配置     | JSON、TOML、原配置保留、预览后外部改动、写入失败、精确卸载     |
| 真实验收 | CLI 任务、App 任务、现有其他 Hook、Bridge 修复                 |

## 完成门槛

- 阶段一到四各自的相邻单元测试通过；
- pnpm run typecheck、pnpm run test、pnpm run build 通过；
- src-tauri 中 cargo test 通过；
- 在临时目录完成配置写入与卸载测试；
- 至少在一台 Windows 环境中分别完成 CLI 与 App 的真实 Hook 验收；
- 未修改无关业务模块，未引入用户配置样本、日志正文或敏感数据。
